# Test Plan: Приложение "TaskFlow"

## 1. Введение
Данный документ описывает стратегию, объем и подход к тестированию веб-приложения TaskFlow.

## 2. Область тестирования (Scope)

**Входит в тестирование (In Scope):**
- Функциональность добавления задач (UI).
- API методы (GET /api/tasks, POST /api/tasks).
- Валидация входных данных (пустые поля, граничные значения).
- Сохранение данных в базе данных SQLite.
- Проверка адаптивности верстки (DevTools).
- Нагрузочное тестирование базового сценария.

**Не входит (Out of Scope):**
- Авторизация и аутентификация (в текущей версии отсутствуют).
- Редактирование и удаление задач (в бэклоге на будущее).

## 3. Виды тестирования
- **Функциональное:** Проверка соответствия User Stories (US-1, US-2, US-3). 
- **UI/UX:** Проверка верстки, отображение ошибок.
- **API:** Проверка статус-кодов, структура JSON.
- **Интеграционное:** Проверка связи Фронтенд -> Бэкенд-> БД.
- **Нагрузочное:** Проверка стабильности сервера при пиковых нагрузках.

## 4. Инструменты
- **DevTools:** Исследовательское тестирование, анализ Network (запросы/ответы).
- **Postman:** Ручное и автоматизированное тестирование API.
- **DBeaver / SQLite:** Верификация данных в БД (Test Data Management).
- **Charles:** Эмуляция сетевых проблем (подмена ответов).
- **Mockoon:** Тестирование заглушек (delay, server errors).
- **JMeter:** Нагрузочное тестирование.
- **Git / GitHub:** Контроль версий и хранение артефактов.

## 5. Критерии начала (Entry Criteria)
- Развернуто локальное окружение (Python + Flask).
- Подготовлены тестовые данные.


## 6. Критерии завершения (Exit Criteria)
- Все тест-кейсы из чек-листа пройдены.
- Критические (Blocker) и высокоприоритетные (High) баги исправлены.
- Сформирован отчет о тестировании.
