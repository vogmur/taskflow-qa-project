# PRD: Приложение "TaskFlow" (Мини-таск-менеджер)

## 1. Цель продукта
Создать легковесное веб-приложение для управления личными задачами, позволяющеепользователюдобавлять задачи и отслеживать их статус.

## 2. Целевая аудитория
Пользователи, которым нужен простой список дел без перегруженного интерфейса.

## 3. Функциональные требоввания (User Stories)

### US-1: Просмотр списка задач
- **Как** пользователь, **я хочу** видеть список всех своих задач на главной странице, **чтобы** понимать, что мне нужно сделать.
- **Критерии приемки:** 
- При открытии страницы отображается список задач.
- Если задач нет, отображается пустой список (без ошибок).
- Каждая задача отображает свой Title (название) и Status (статус).

### US-2: Создание задачи
- **Как** пользователь, **я хочу** иметь возможность добавить новую задачу, **чтобы** не забыть о ней.
- **Критерии приемки:**
- На странице есть поле ввода "Title" и кнопка "Добавить".
- При вводе текста и нажатии кнопки задача сохраняется и сразу появляется в списке.
- Поле ввода очищается после успешного добавления.

### US-3: Валидация пустого поля
- **Как** система, **я должна** предотвращать создание задач с пустым названием.
- **Критерии приемки:**
- Если поле пустое или содержит только пробелы, при нажатии кнопки выдается сообщение об ошибке (Alert).
- Задача не создается.
- API возвращает ошибку 400 Bad Request.

## 4. Нефункциональные требования
- **Производительность:** Сервер должен выдерживать до 100 одновременных запросов на чтение (GET) без падения.
- **Совместимость:** Корректное отображение в последних версиях Chrome, Firefox, Edge.
